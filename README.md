# Блог на чистом PHP + Smarty + MySQL

Bento Editorial — тестовое задание без фреймворков: PHP 8.2 (код PHP 8.1+), Smarty 5, MySQL 8.4, PDO, SCSS/Dart Sass, nginx и Docker Compose. Единственная прямая Composer-зависимость — Smarty.

Что есть: главная (непустые категории, по 3 свежие статьи, «Все статьи»), категория (описание, сортировка по дате и просмотрам, пагинация), статья (все поля и 3 похожие), сидинг категорий и статей. Сверх ТЗ: подписка на рассылку и подгрузка списка без перезагрузки на странице категории.

## Быстрый старт (Docker)

Нужны только Docker с Compose v2 и интернет для первой сборки. PHP, Composer и Node на машине не нужны. Порт 8080 должен быть свободен (или задайте `WEB_PORT` в `.env`).

```sh
git clone <адрес-репозитория> blog && cd blog
cp .env.example .env        # PowerShell: Copy-Item .env.example .env
docker compose up -d --build
```

Всё. Команда сама собирает образы (SCSS собирается внутри), поднимает MySQL, создаёт таблицы и заполняет базу (6 категорий, 40 статей): за это отвечает одноразовый сервис `setup`, сайт стартует только после него. Первая сборка занимает несколько минут. Открыть: <http://localhost:8080>.

Если что-то не так: `docker compose logs setup` покажет миграцию и сид, `docker compose ps` — состояние сервисов. Полный сброс вместе с данными: `docker compose down -v`.

Значения в `.env.example` рассчитаны на локальный запуск. Для сервера задайте свои пароли и `APP_ENV=production`; смена паролей в `.env` не меняет пользователей уже созданного тома MySQL.

Ручной запуск миграции и сида (если нужно повторить): `docker compose exec app php bin/migrate.php` и `docker compose exec app php bin/seed.php`; подробности — в разделе «Миграция и сид».

Страницы для просмотра:

- [Главная](http://127.0.0.1:8080/)
- [Архитектура](http://127.0.0.1:8080/category/architecture)
- [Сортировка по просмотрам, страница 2](http://127.0.0.1:8080/category/architecture?sort=views&page=2)
- [Статья](http://127.0.0.1:8080/post/sustainable-systems)
- [Изолированная статья с добивкой похожих](http://127.0.0.1:8080/post/deployment-checklist)
- [Пустая категория](http://127.0.0.1:8080/category/editorial-notes)
- [404](http://127.0.0.1:8080/missing)

Адреса `/category` и `/post` возвращают 404. Все ссылки карточек и категорий ведут на реальные slug-маршруты. Авторы, время чтения, подписи к изображениям, теги и дополнительные действия удалены по подтверждению владельца. Подписка вне ТЗ возвращена по запросу владельца (раздел «Подписка»).

## Окружение

| Переменная | Назначение |
|---|---|
| MYSQL_DATABASE | База, по умолчанию bento |
| MYSQL_USER | Пользователь приложения, по умолчанию bento |
| MYSQL_PASSWORD | Пароль приложения; в примере локальное значение, на сервере заменить |
| MYSQL_ROOT_PASSWORD | Отдельный пароль root; в примере локальное значение, на сервере заменить |
| WEB_PORT | Порт сайта на хосте, по умолчанию 8080 |
| APP_ENV | development по умолчанию; только это точное значение разрешает --fresh и разрушительные проверки |
| SEED_DATE | YYYY-MM-DD для воспроизводимого сида; пусто = сегодня UTC |

Приложение получает DB_HOST=db, DB_PORT=3306, DB_DATABASE, DB_USER, DB_PASSWORD. Для сервера нужны собственные секреты, APP_ENV=production и отдельный порядок обновления; вывод ошибок выключен во всех окружениях.

## Миграция и сид

```sh
docker compose exec app php bin/migrate.php
docker compose exec app php bin/seed.php
docker compose exec app php bin/seed.php --help
# Только APP_ENV=development: полная замена данных и просмотров
docker compose exec app php bin/seed.php --fresh
docker compose exec app php bin/seed.php --fresh --categories=8 --posts=64
```

Стандартный набор: 6 категорий, 40 самостоятельных тем, 65 связей. Архитектура — 25 статей, дизайн — 10, технологии — 20, культура — 9, инженерная практика — 1, заметки редакции — 0. 22 статьи (55%) имеют несколько категорий. Категории распределены по кругу; последняя активная категория изолирована. Сохранены равные даты и начальные просмотры 0–5000. При чтении сайта просмотры закономерно выходят за начальный диапазон.

Минимальные параметры — 4 категории и 12 статей, чтобы сохранить граничные случаи; при стандартных 40 статьях используются 40 разных тем без суффиксов. Для наборов больше 40 темы повторяются с номером выпуска. Даты находятся в пределах 360 дней до SEED_DATE; одинаковая опорная дата даёт воспроизводимое содержимое.

Обычный сид сохраняет существующие тексты и просмотры по уникальным slug и добавляет недостающие связи. Он не удаляет старые строки или связи. Для обновления старого демонстрационного набора после правок нужен --fresh в development. CLI проверяет окружение до генерации файлов, репозиторий — до транзакции удаления. Production, staging и отсутствие APP_ENV отклоняются; это подтверждено хешем неизменившейся БД.

Иллюстрации — постоянная библиотека из 10 сгенерированных редакционных фотографий в public/assets/images/editorial/. Перед добавлением в проект исходные PNG преобразованы в WebP (1200×800); суммарно около 1,2 МБ. Сид выбирает изображения по кругу, на стандартных 40 статьях каждое используется четырежды. Генерация изображений и сетевые запросы при запуске сида не выполняются, --fresh не удаляет библиотеку. Файлы включены в Git и Docker-образы; для них не нужен том uploads. Сам том uploads сохранён для пользовательских загрузок: app пишет, nginx читает.

Для перевода существующих статей на библиотеку после пересборки: `docker compose exec app php bin/refresh-images.php`. Команда меняет только image, сохраняя тексты, категории и просмотры; повторный запуск идемпотентен. Обычный сид сохраняет существующие изображения. Новые статьи сида автоматически используют эту же десятку.

[Состав библиотеки и промпты](design/editorial-images.md), [отчёт проверки](docs/reports/editorial-images.md). Проверки: `node tools/check-seed-assets.cjs`, `node tools/check-editorial-images.cjs`; для проверки обновления и сохранности данных: `Get-Content -Raw tools/check-image-library.php | docker compose exec -T -e APP_ROOT=/var/www/html app php`.

Начальная миграция использует CREATE TABLE IF NOT EXISTS. Она идемпотентна, но не исправляет произвольные несовместимые таблицы; будущие ALTER требуют отдельных миграций. DDL MySQL не объявляется одной откатываемой транзакцией.

## Структура и поведение

```text
public/index.php             точка входа
config/bootstrap.php         явная сборка зависимостей и маршрутов
src/Core/                    Router, Application, Database, View, Response, Config
src/Model/                   Category и Post с readonly-свойствами
src/Repository/              весь SQL приложения и сида
src/Service/                 подготовка страниц, presenters, учёт просмотров
src/Controller/              тонкие контроллеры
src/Seeder/, bin/, database/  генерация данных, CLI и схема
templates/partials/          общая разметка
assets/scss/                 токены, миксины, компоненты, страницы и движение
public/assets/fonts/         локальные шрифты с лицензиями
public/assets/images/editorial/ 10 постоянных WebP-иллюстраций
var/                         Smarty cache и локальные отчёты, не Git
docs/reports/                сохранённые EXPLAIN
```

Router принимает GET и HEAD (страницы) и POST (только /subscribe), валидирует slug как [a-z0-9-]+ и разбирает query string. Application выдаёт 404/405/500; HEAD сохраняет заголовки и убирает тело. БД подключается внутри обработчиков, поэтому ошибка соединения не мешает отрисовать нейтральную страницу ошибки. DTO содержат типизированные неизменяемые данные. Даты, ссылки, подписи просмотров и поля представления формируются в сервисах, а не SQL.

Главная делает три запроса: непустые категории; все тройки последних статей через ROW_NUMBER с PARTITION BY category_id; все категории найденных статей через один IN. Оконная функция нумерует статьи отдельно в каждом разделе по published_at DESC, id DESC; остаются номера 1–3. Первый пост секции имеет вариант large. Для полностью пустой БД достаточно двух запросов — пакет категорий постов пуст.

Категория: whitelist date/views, неверный sort → date; всегда вторым ключом id DESC. page приводится к int и ограничивается снизу единицей, массивы параметров обрабатываются безопасно. По 9 статей, за последней страницей — 404. Пустой раздел доступен на первой странице. Пагинатор сохраняет sort; смена сортировки начинает список с первой страницы. OFFSET прост для небольшого блога; глубокие страницы на больших наборах дороже.

Статья: каждый GET увеличивает views одной атомарной командой `UPDATE posts SET views = views + 1`. **Это демонстрационное правило:** один переход или обновление страницы считается просмотром, чтобы сортировку по просмотрам было легко проверить руками (комментарий с тем же пояснением лежит в `ViewTracker`). В боевом блоге нужна дедупликация (сессия или окно по IP) и фильтр ботов; атомарный UPDATE остаётся прежним. HEAD просмотры не увеличивает и не создаёт сессию. Ответ статьи private, no-store.

Похожие: один SQL с двумя LEFT JOIN и COUNT. Для каждой другой статьи считаются общие категории с текущей. Выше больше совпадений, затем свежая дата и больший id. Нулевые совпадения остаются в результате и добивают список до трёх; если во всей БД меньше трёх других статей, показываются доступные. Используются разные :source_id и :excluded_id: [PDO запрещает повтор одного именованного параметра при native prepares](https://www.php.net/manual/en/pdo.prepare.php). См. также [оконные функции MySQL](https://dev.mysql.com/doc/refman/8.4/en/window-functions-usage.html).

Планы выполнения и их ограничения: [EXPLAIN этапов 3–5](docs/reports/stages-3-5-explain.md). Категория на тесте с 10 040 статьями использует индекс связи и PRIMARY posts. Для окна и ранжирования похожих обработка набора кандидатов и сортировка ожидаемы.

## Проверки

Для инструментов на хосте нужны PHP CLI/Composer и Node: composer install, npm ci. Сам сайт работает в Docker. Основные проверки:

```powershell
php tools/check-core.php
npm run check:views
Get-Content -Raw tools/check-blog.php | docker compose exec -T -e APP_ROOT=/var/www/html app php -- --exercise-large | Set-Content -Encoding utf8 var/blog-checks.json
node tools/check-blog-http.cjs
Get-Content -Raw tools/check-seed-guard.php | docker compose exec -T -e APP_ROOT=/var/www/html app php
node tools/check-stage1.cjs
node tools/check-visual.cjs
```

--exercise-large разрешён только в development, добавляет 20 временных категорий и 10 000 статей в откатываемых транзакциях. Обычный check-blog.php также проверяет постоянное число запросов временным расширением категорий с последующим откатом; запускайте его в тестовой БД. Счётчик PDOStatement::execute включён исключительно инструментом, отладочного HTTP-маршрута нет. HTTP-проверка читает свежий var/blog-checks.json, сверяет порядок с БД, проверяет границы и реально увеличивает просмотры.

В bash вместо Get-Content используйте перенаправление: `docker compose exec -T -e APP_ROOT=/var/www/html app php -- --exercise-large < tools/check-blog.php > var/blog-checks.json`.

Отдельная проверка исходного сида требует набора сразу после --fresh, до чтения статей и ручных правок. Она проверяет в том числе начальный диапазон просмотров и детерминированность; --exercise меняет и пересоздаёт данные:

```powershell
docker compose exec -T app php bin/seed.php --fresh
Get-Content -Raw tools/check-stage2.php | docker compose exec -T -e APP_ROOT=/var/www/html app php -- --exercise
node tools/check-seed-assets.cjs
```

Логи: docker compose logs app. Проверка реального FPM-исключения: `Get-Content -Raw tools/check-fpm-logging.php | docker compose exec -T -e APP_ROOT=/var/www/html app php`. Она создаёт временный файл вне public и удаляет его после проверки. `node tools/check-stage1-review.cjs` проверяет HEAD и сохранённый проверочный файл uploads этапа 1; в новом окружении сначала создайте этот файл по отчёту этапа 1.

## Подписка (сверх ТЗ)

Кнопка «Подписаться» в шапке открывает попап, такая же форма стоит на главной между категориями (не первой и не последней; при трёх категориях и меньше — в конце). Попап и мобильное меню используют нативный HTML Popover API (popovertarget), поэтому работают без JavaScript при script-src 'none'. Форма отправляет POST /subscribe: проверка CSRF-токена из сессии (hash_equals), валидация адреса (FILTER_VALIDATE_EMAIL, до 254 символов), запись одной подготовленной командой INSERT ... ON DUPLICATE KEY UPDATE в таблицу subscribers (повторный адрес не создаёт дубль и не раскрывается). Результат показывает отдельная страница. Ограничений частоты запросов и подтверждения адреса письмом нет. Таблица создаётся bin/migrate.php: после обновления выполните docker compose up -d --build и docker compose exec app php bin/migrate.php.

## SCSS и анимации

```sh
npm ci
npm run build:css
npm run watch:css
# Чтобы сайт получил новые стили/шаблоны/код:
docker compose up -d --build
```

Собранный CSS не коммитится. SCSS собирается Node-стадией Docker, runtime не содержит Node. BEM, сетка, токены цветов и один chamfer-миксин сохранены. Макеты были сделаны в Google Stitch и перенесены в шаблоны Smarty; в репозитории они не хранятся. Подключены локальные Unbounded, Manrope, Source Serif 4, Space Mono; SIL OFL рядом с файлами. Повторное получение — node tools/fetch-fonts.cjs.

CSS-движение сосредоточено в tokens/_motion.scss, mixins/_motion.scss, base/_motion.scss. Сборка плиток с посадкой проигрывается только при заходе на сайт (сервер добавляет html.is-nav по Sec-Fetch-Site, когда посетитель перешёл по ссылке внутри сайта), между страницами работает один view transition, шапка при этом неподвижна. Сборка плиток с посадкой, inset-маски, hover у интерактивных элементов, reduced motion, progressive scroll/view transitions работают без JavaScript. Проверки:

```sh
npx playwright install firefox
node tools/check-motion.cjs
node tools/check-motion-performance.cjs
```

Кадры 390/1440, reduced motion и настоящий Firefox без view timeline сохраняются в var/motion. Скрипты управления временем существуют только в тестах. Служебный пересчёт стилей зависит от браузера, поэтому полное отсутствие Recalculate не заявляется. Исторический сравнительный Lighthouse анимаций (до подключения БД): Performance 97/97, Best Practices 96/96, CLS 0.00445/0. Эти оценки не переносятся автоматически на новые страницы с БД. Полный аудит остаётся этапом 7.

## Безопасность и ограничения

PDO использует настоящие prepared statements и исключения, соединение utf8mb4; значения сортировки выбираются только из фиксированной карты. Smarty автоматически экранирует текст; единственный nofilter — доверенный HTML статьи. Сид создаёт его из белого списка тегов и экранированного текста. Импорт произвольного пользовательского HTML и админка не реализованы.

CSP разрешает только локальные ресурсы: скрипты только со своего origin, inline-скрипты и inline-стили запрещены, внешние картинки тоже и внешние картинки. nginx скрывает версию, закрывает служебные пути и исполнение PHP в uploads. App работает от www-data, MySQL-порт не опубликован, ошибки идут в stderr, посетителю не показываются подробности. Секреты и runtime-файлы исключены из Git. Полный аудит безопасности, чистый клон и итоговый Lighthouse — последующие этапы; их прохождение не заявлено.

## Эксплуатация

Остановка с сохранением данных: docker compose down. Полное удаление БД и uploads: docker compose down -v — только для осознанного сброса локального окружения. Перед обновлением сохраните дамп MySQL и отдельно том uploads; восстановление обоих нужно проверить в отдельном окружении. Для сервера потребуются HTTPS/reverse proxy (например nginx или Caddy), закрытый прямой доступ к dev-порту и собственные секреты. Развёртывание на публичном сервере и восстановление из бэкапа пока не проверялись.

Обновление локально: docker compose up -d --build, затем bin/migrate.php. Сид на сервере не является миграцией пользовательских данных, --fresh там запрещён.

## Навигация и сортировка

Шапка на любой странице показывает «Главная» и первые три категории; остальные лежат в выпадающем списке «Остальное» (открывается наведением и фокусом клавиатуры, без JavaScript). В мобильном меню видны все категории. Сортировка и пагинация на странице категории подгружаются без перезагрузки (`public/assets/js/listing.js`, около 70 строк, `fetch` плюс `history.pushState`): адрес меняется, прямые ссылки и кнопка «Назад» работают, а без JavaScript те же ссылки открываются обычными переходами. Категории для шапки и подвала берутся на каждой странице из БД, поэтому выбор категории не прячет остальные.

Сортировка категории: `?sort=date|views&dir=desc|asc`. Повторный клик по активному варианту меняет направление (↓ новые/популярные сначала, ↑ старые/малопросматриваемые сначала); переход на другой вариант начинается с `desc`. Колонка и направление берутся только из белого списка, значения в запрос подставляются как константы; пагинация сохраняет оба параметра.

## Использование ИИ


ИИ использовался для подготовки макета, настройки окружения, ревью кода и документации. Работа велась поэтапно, с ручной доработкой и проверкой результата.

- **Дизайн и вёрстка.** За основу взят референс из интернета. Первая версия макета собрана в Google Stitch, затем перенесена в HTML. После этого выделены стили и дизайн-токены, стили организованы в SCSS. Разметка вручную разделена на блоки и шаблоны Smarty.
- **Окружение.** Docker-окружение подготовлено с помощью Claude.
- **Подключение к PHP и ревью.** После интеграции вёрстки с PHP Claude использовался для ревью кода, проверки безопасности, SQL-запросов и соответствия ТЗ. Вручную доработаны логика навигации в шапке, мобильная версия и AJAX-подгрузка статей на странице категории. Проведено ручное тестирование.
